# Design Gate Rules

## Rule 1: Stop-the-line при отсутствии Figma-спецификации
Перед созданием или изменением любого UI-компонента или экрана агент **обязан** получить точную спецификацию макета:
- вызвать `get_design_context` (и при необходимости `get_screenshot`) через Figma MCP для целевого `node_id`;
- если в текущей сессии Figma MCP недоступен, инструмент возвращает ошибку, либо в задаче нет точного `node_id` (или скриншота с параметрами от пользователя) — **категорически запрещено** верстать «на глаз», по памяти или подбирать иконки/размеры наугад;
- агент обязан остановиться, зафиксировать блокер и запросить недостающий доступ, `node_id` или точные параметры у пользователя.

## Rule 2: Запрет на ослабление правил из-за проблем окружения
Отсутствие Figma MCP или другого инструмента в конкретной сессии является локальным блокером окружения. Запрещено удалять или ослаблять требования работы с Figma MCP в проектных правилах и документации из-за такого блокера.

## Rule 3: Спецификация и фазовый шлюз до правок
- Если в запросе пользователя есть вопрос («Почему?», «Как?»), сначала даётся полный текстовый ответ, и только затем (после подтверждения/постановки задачи) выполняются изменения кода, git или сборки.
- Перед правкой Compose-кода агент обязан сверить иерархию контейнеров, размеры, отступы, радиусы, границы, тени, токены `MaterialTheme.colorScheme`, типографику и точные Hugeicons-векторы (`ic_huge_*`).
- При расхождении между устным описанием/старым отчётом и целевым фреймом Figma агент обязан остановиться и уточнить приоритетный источник у пользователя.
