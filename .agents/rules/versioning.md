# Automatic Release Versioning Rule

## Обязательный инкремент версии перед пушем в main

Перед каждым пушем коммитов в ветку `main`, содержащих изменения в кодовой базе приложения (`app/src/` или конфигурации сборки/зависимостей), агент **обязан** инкрементировать версию приложения в `app/build.gradle.kts`:

1. `versionCode`: увеличить строго на `+1` (например, `26` → `27`).
2. `versionName`: увеличить патч-версию семантического версионирования (например, `"1.0.25"` → `"1.0.26"`).

### Исключения и правила группировки:
- Изменения, затрагивающие **исключительно** документацию (файлы в `docs/`, `*.md` документация, CI workflow файлы, комментарии к PR), версию не инкрементируют.
- Инкремент версии выполняется строго **один раз на логический пуш / PR** в ветку `main`.
- Если в рамках одной задачи или пуша делается серия связанных коммитов (пошаговая реализация, хотфикс замечаний ревьюера и т.д.), версию запрещено поднимать повторно на каждый коммит: достаточно одного итогового бампа на всю цепочку коммитов перед отправкой (`push`) в `main`.
