## Прямая проверка Room и private files — PASS

Исходный Google Play AVD не предоставляет root-доступ к private-данным release-приложения. Для прямой проверки того же APK подготовлен отдельный Google APIs API 37 / 16 KB AVD с профилем Pixel 7, `emulator-5556`. Это дополнительная среда для проверки инвариантов хранения; её результаты не являются инспекцией данных исходного Pixel 9.

Установленный APK прочитан обратно и имеет тот же SHA-256; package flags не содержат DEBUGGABLE. Root предоставлен ОС дополнительного AVD, APK не модифицировался. Все изменения состояния приложения выполнены через UI. Private-данные только читались: сохранены архивы `databases`/`files`, копии SQLite вместе с WAL, JSON строк Room и размеров/SHA-256 аудиофайлов. `PRAGMA integrity_check` во всех снятых копиях — `ok`.

Evidence относительно `build/qa-open-items-20260923/root/`; каждый каталог снимка содержит `snapshot.json` и исходные данные.

## Итог и состояние среды

Сверены все шесть снимков: целостность SQLite, согласованность `isDownloaded`/пути/файла, отсутствие лишних файлов, уникальность очереди, разные имена новых файлов, окончательное удаление при отписке. Результат `root/verification.json` — PASS. Crash buffer дополнительного AVD пуст (`root/crash-buffer.txt`). Это проверки evidence, а не новый прогон полного набора Android/JVM tests. `git diff --check` прошёл.

Дополнительный AVD остановлен, его данные и evidence сохранены; исходный Pixel 9 оставлен работающим. Временный fixture-сервер остановлен, reverse tcp:8765 снят с обоих AVD. Совместимый обработчик старого endpoint сохранён в `build/qa-open-items-20260923/fixture-compatible.py`; снимки делает `snapshot_release.py` в той же папке. Код приложения в этом продолжении не менялся, APK не пересобирался. Коммит, push и публикация не выполнялись. Следующим остаётся отдельно согласованный третий технический этап; два прежних ограничения повторно открывать без новых фактов не нужно.
